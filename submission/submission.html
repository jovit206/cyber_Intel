Project description

A FastAPI / MongoDB threat-intelligence dashboard (Lab 7) running on a three-member MongoDB 7.0 replica set rs0 (Lab 8), together with the Lab 9 write-concern latency benchmark and network-partition experiment. It is delivered as one application image plus the official mongo:7.0 image, orchestrated by Docker Compose with persistent named volumes.

Compose starts the three MongoDB members, initialises rs0 only if needed (idempotent), then starts the application. Data lives in named volumes and survives stop, down and upgrades.

Features

  • Lab 7: Live Threat Stream, Top Threats, Report Corpus, Search & Enrich (VirusTotal, 24 h cache), Cross-Source Analysis, Working Set Monitor (live WiredTiger cache telemetry).
  • Lab 8: three-member replica set, member and primary monitoring, failover observer (labs/lab8).
  • Lab 9.1: write-concern latency for w:1, w:majority, w:all (numeric w = member count) with j:false/j:true, 1,000 inserts each; JSON/CSV artifacts; historical vs live results separated in the UI.
  • Lab 9.2: confirmed, reversible network-partition simulation with prechecks, timestamps, honest write outcomes and verified recovery.

Safety notes

  • The partition experiment and the live benchmark never run automatically (build, start-up, tests, publication).
  • Only a secondary is isolated by default; the primary is never selected. Containers, volumes, replica-set configuration and documents are not removed.
  • docker compose down -v deletes database volumes and is not part of any procedure.
  • No secrets are in the image: .env is excluded; the VirusTotal key is read by the backend at run time only.
  • MongoDB is bound to loopback host ports and runs without authentication inside the internal network.
